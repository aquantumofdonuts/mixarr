# Mixarr v3.0.0 — discover music with context

**Released October 29, 2026. Available now for AMD64 and ARM64.**

Mixarr v3.0.0 is here. Bring playlists, charts, listening history, and recommendations into a compact music catalog, see why an artist appeared, and review discoveries before sending them to Lidarr.

The new Collaboration Constellation gives you another route to your next discovery: follow the musicians, producers, songwriters, and engineers credited on records you love. Inspect their roles and releases, explore paths between people, and request an artist or an individual album in Lidarr.

[See the website](https://aquantumofdonuts.github.io/mixarr/) · [Install Mixarr](https://github.com/aquantumofdonuts/mixarr/blob/prod/README.md#quick-start) · [Upgrade your installation](https://github.com/aquantumofdonuts/mixarr/blob/prod/README.md#upgrading)

## Highlights

- Artwork rows across Discovery, Search, Library, Subscriptions, Queue, Connections, and Settings. A shared artist inspector keeps identity, library membership, provenance, and releases together without losing list context.
- Collaboration Constellation explores credited musicians, producers, songwriters, and engineers. Follow paths, filter roles, preview tracks, and request individual albums or artists in Lidarr. The graph retains its 300-person cap; live Discogs is the default, with an optional local dump index.
- Acquisition feedback distinguishes newly added, already present, failed, uncertain, and identity-required outcomes. Review decisions have revision-bound Undo, ownership checks, and stable queue cursors.
- Refreshed settings, connection feedback, responsive layouts, dialogs, keyboard focus, branding, screenshots, and website.

## Fixes and upgrade reliability

- Saved slskd connections now have a working Test action ([#66](https://github.com/aquantumofdonuts/mixarr/issues/66)).
- Manual slskd searches use a 30-second default accepted by Mixarr, with seconds converted to milliseconds at the slskd boundary; compound terminal states also reveal the results ([#88](https://github.com/aquantumofdonuts/mixarr/issues/88)). The timeout is an API option; this release does not add a persistent UI setting for it.
- The slim image works through its bundled frontend proxy without an `API_URL` override; setup/login over plain HTTP preserves authentication ([#60](https://github.com/aquantumofdonuts/mixarr/issues/60)).
- Released v2.0, v2.1–v2.2, and v2.3 schemas upgrade directly. Checked enum expansions preserve historical values, and constellation tables are added without removing existing records or unmanaged tables.
- Startup waits for database/Redis readiness and restored schedules before queue workers and HTTP requests resume. Failed migrations and unsupported schema drift stop safely.
- Both published image variants have automated upgrade, restart, drift-rejection, frontend-proxy, and fresh-install checks. Publication requires tested production code and matching version metadata.

## Upgrading

Back up the database and persistent data first. Keep the same volumes, connection configuration, and `SESSION_SECRET`. Upgrade the bundled web/API together using `ghcr.io/aquantumofdonuts/mixarr:v3.0.0` or `:v3.0.0-slim` and your existing deployment configuration. Containers verify the schema and apply checked migrations automatically; no data reset or intermediate v2 release is required.

For an existing Compose service named `mixarr`, update its image tag in your existing Compose file, then run:

```bash
docker compose pull mixarr
docker compose up -d --no-deps mixarr
docker compose logs --tail=100 mixarr
```

Keep your existing `.env` and database/Redis services. Do not regenerate the session secret or delete volumes. Allow for a brief application restart, then refresh the browser. Docker Run and Unraid users should retain their saved environment and data mappings when recreating/updating the container. See the [upgrade guide](https://github.com/aquantumofdonuts/mixarr/blob/prod/README.md#upgrading) for source deployments and recovery details.

Source deployments run `npm ci`, `npm run db:generate`, and `npm run db:deploy --workspace=@mixarr/api` before starting the API. Run migrations once before starting multiple replicas. If the schema guard stops startup, inspect the error and backup; do not reset the database or force acceptance of data loss.

Rollback requires restoring the pre-upgrade database/data backup. An in-place downgrade to v2.3.5 can remove newly created tables through its old schema-sync path.

## Breaking API changes

- Review decisions accept `approved` or `rejected`; restore an eligible rejection through its Undo token instead of setting `pending` directly.
- Bulk review requests accept at most 100 IDs. Responses provide per-record `outcomes` and separate counts; HTTP 200 does not confirm that every item was added. The old `failedItems` shape is removed.
- Label pagination uses `releasesProcessed`, `totalReleases`, and `nextReleaseOffset`; advance by release offset rather than artist count.

## Verification and limits

The release passed application tests, type checks, builds, CodeQL, browser smoke tests, real MySQL migration regressions, and both Docker variants' released-v2 upgrade rehearsals. Each published AMD64 and ARM64 image passed upgrade, retained-session, restart, drift-rejection, frontend-proxy, and fresh-install checks. The versioned and stable registry manifests were verified against those tested image digests before publication of this announcement.

Live provider verification remains separate work. TIDAL endpoint compatibility ([#81](https://github.com/aquantumofdonuts/mixarr/issues/81)), Jellyfin authentication compatibility ([#87](https://github.com/aquantumofdonuts/mixarr/issues/87)), and other integration/security findings remain tracked in [known issues](https://github.com/aquantumofdonuts/mixarr/blob/prod/docs/ISSUES.md); this release does not claim they are resolved. Album-selection and subscription-reporting requests with remaining requirements stay open.

Thanks to everyone who reported issues and shared troubleshooting details, especially NAM1025, jordanhaven, logicalstorm, and Dimppu for helping track down the slim and slskd fixes. If a problem persists after upgrading, please [open an issue](https://github.com/aquantumofdonuts/mixarr/issues) with the image tag, deployment method, and logs with secrets removed.
