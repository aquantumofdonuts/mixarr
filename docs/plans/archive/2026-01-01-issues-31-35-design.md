## Issue 31: Users/Settings Access Control

### Problem
Non-admin users incorrectly see the "Users" link in the sidebar, and the avatar menu navigates to `/settings` which may show admin-only content.

### Solution

1. **Add `adminOnly: true`** to the Users nav item in `sidebar.tsx`
2. **Create `/users/me` page** — A personal settings page for non-admin users
3. **Update avatar menu** — Navigate to `/users/me` instead of `/settings` for non-admins

### Files to Modify
- `apps/web/src/components/layout/sidebar.tsx` — Add adminOnly flag, update avatar menu
- `apps/web/src/app/users/me/page.tsx` — New file for personal settings

### Implementation Notes
- The `/users/me` page should show: profile info, password change, personal preferences
- Reuse existing settings components where possible
- Keep `/settings` for admin-only system configuration

## Issue 33: UI Updates - Larger Thumbnails + External Links

### Problem
Artist thumbnails are too small (40-48px), and there are no quick links to external services like Spotify or Last.fm.

### Solution

1. **Grid-based responsive thumbnails**
   - Desktop: ~80px thumbnails in grid layout
   - Tablet: ~64px thumbnails, fewer columns
   - Mobile: ~56px thumbnails, 2 columns
   
2. **Icon-only external link buttons**
   - Spotify (green) — Link to artist on Spotify
   - Last.fm (red) — Link to artist on Last.fm
   - MusicBrainz (orange) — Link to MusicBrainz page
   - Compact icons, no text labels

### Files to Modify
- `apps/web/src/app/search/page.tsx` — Update artist cards
- `apps/web/src/app/discover/page.tsx` — Update artist cards
- `apps/web/src/app/preview/page.tsx` — Update artist display
- Consider creating shared `ArtistCard` component

### Implementation Notes
- Use Tailwind responsive classes: `w-14 h-14 sm:w-16 sm:h-16 md:w-20 md:h-20`
- External links open in new tab (`target="_blank"`)
- Only show external links if URL is available in artist data

## Issue 34: Better Logging for Artist Additions

### Problem
When artists are added from search/discover, there's no record in the activity feed.

### Solution

**Standard logging** with the following fields:
- Artist name
- Source (Search, Discover, Import)
- User who performed the action
- Success/failure status
- Timestamp

### Files to Modify
- `apps/api/src/services/lidarr.service.ts` — Add logging after successful artist add
- `apps/api/src/services/activity.service.ts` — May need new activity type
- `apps/web/src/app/search/page.tsx` — Ensure add action calls logging endpoint
- `apps/web/src/app/discover/page.tsx` — Ensure add action calls logging endpoint

### Implementation Notes
- Create `ARTIST_ADDED` activity type if not exists
- Log should include: `{ artistName, source, userId, status, timestamp }`
- On failure, include error message but not full stack trace
